AlphaFold3

QUICK SUMMARY
AlphaFold3 predicts a protein's 3D structure — or a protein bound to a peptide, macrocycle, or small molecule. It doesn't dock the way AutoDock/Glide does (scoring poses against a fixed receptor); it co-folds the whole complex from scratch in one pass, giving back one predicted structure with a confidence score. Installed and verified working on Woody — see below for what's already been tested.

Before you start

Weights and the ~630GB genetic database set are shared on /data — nothing to download per person, every user's runs point at the same copy. You just need to be in the docker group (ask Andrew or whoever administers Woody, then log out and back in). Your own input/output go in ~/af3/input/ and ~/af3/output/.

Quick start — fold a single protein

FFA4 (Free Fatty Acid Receptor 4 / GPR120) — the group's own target — is used as the worked example throughout this section, so the numbers you see are real, not made up.

HOW TO — fold a single protein

1. Get a sequence. A protein sequence is a string of one-letter amino acid codes (a FASTA sequence). If you don't have one, get it from UniProt.

2. Save an input JSON in ~/af3/input/:

{
  "name": "ffa4_monomer",
  "sequences": [{ "protein": { "id": "A", "sequence": "YOUR_SEQUENCE_HERE" } }],
  "modelSeeds": [1],
  "dialect": "alphafold3",
  "version": 4
}

id is just a chain label — leave it "A" for a single-chain job. modelSeeds controls sampling — [1] is fine to start with.

3. Run it:

docker run -it \
    --volume $HOME/af3/input:/root/af_input \
    --volume $HOME/af3/output:/root/af_output \
    --volume /data/20260825_AndrewR_af3/models:/root/models \
    --volume /data/20260825_AndrewR_af3/databases:/root/public_databases \
    --gpus all \
    alphafold3 \
    python run_alphafold.py \
    --json_path=/root/af_input/ffa4_monomer.json \
    --model_dir=/root/models \
    --output_dir=/root/af_output

Two stages run back to back. Data pipeline (CPU only) — searches genetic databases to build an alignment profile (MSA). The slow part: minutes for a small protein, up to ~10–15 min for something FFA4's size (297 residues) — normal, not stuck. Inference (GPU) — the actual structure prediction, usually under a minute on our A5500s. Results land in ~/af3/output/<name>/<name>_model.cif.

Reading your results

The scores live in <name>_summary_confidences.json. For the FFA4 monomer run above (real numbers, timings: data pipeline 441s, inference 53s on one A5500):

MetricThis run's valueWhat it means
ranking_score0.91Overall quality score (0–1.5 scale, higher = better). >0.8 is a strong result.
ptm0.88Confidence in the overall fold. >0.5 = probably right; 0.88 is high confidence.
iptmnullConfidence in an interface between two chains — null here since there's only one chain. Expected for any single-protein job, not an error.
fraction_disordered0.066% of the structure predicted disordered — low, consistent with a well-folded GPCR.
has_clashfalseNo significant atomic clashes.

Rule of thumb for ptm/iptm (0–1 scale): >0.8 confident, trust it · 0.6–0.8 gray zone, check pLDDT/PAE before relying on it · <0.6 low confidence, the model probably didn't get this right.

Two more metrics live in <name>_confidences.json: pLDDT (0–100, per-atom local confidence — which loop/domain to trust) and PAE (predicted error in Å between residue pairs, lower = better — most useful at an interface).

FOR COMPLEXES
Don't just read the global ranking_score/ptm — use chain_pair_iptm (a specific pair of chains you care about) or chain_iptm (a chain's average interface confidence, if you don't know the partner in advance).

Docking: proteins, macrocycles & ligands

This is the part most of the group will actually use — predicting how a peptide, macrocycle, or small molecule sits against a target protein.

Protein + protein (e.g. a linear peptide or a second protein chain): add a second protein entity to sequences, with a different id. AlphaFold3 predicts the joint complex directly — no extra flags needed.

{
  "name": "my_complex",
  "sequences": [
    { "protein": { "id": "A", "sequence": "TARGET_PROTEIN_SEQUENCE" } },
    { "protein": { "id": "B", "sequence": "SECOND_CHAIN_SEQUENCE" } }
  ],
  "modelSeeds": [1], "dialect": "alphafold3", "version": 4
}

Protein + macrocyclic peptide or peptidomimetic — the important one for this group. AlphaFold3's protein entity only understands standard linear natural-amino-acid chains — no head-to-tail cyclization, disulfide staples, D-amino acids, or N-methylation.

CHEMISTRY NOTE — macrocycles & peptidomimetics
Represent the macrocycle/peptidomimetic as a ligand entity via its SMILES string instead (from ChemDraw, RDKit, PepWiz, or hand-drawn) — SMILES ring notation encodes the macrocycle directly, and covers D-amino acids, N-methylation and non-peptide linkers too. This is exactly what a DeepMind AlphaFold3 maintainer recommends for this case (GitHub issue #242): "specify the whole peptide plus covalently bound ligand as SMILES string, treating short peptide as a small molecule."
{
  "name": "target_plus_macrocycle",
  "sequences": [
    { "protein": { "id": "A", "sequence": "TARGET_PROTEIN_SEQUENCE" } },
    { "ligand": { "id": "B", "smiles": "YOUR_MACROCYCLE_SMILES", "description": "macrocycle name" } }
  ],
  "modelSeeds": [1], "dialect": "alphafold3", "version": 4
}

SMILES + JSON: SMILES often contain backslashes (\), which JSON treats as an escape character — double any \ to \\ before pasting, or run python3 -c "import json; print(json.dumps(input()))" to auto-escape.

Protein + small organic ligand — same pattern, an ordinary small molecule instead of a peptide. Worked with TUG-891, a real native FFA4 agonist:

{
  "name": "ffa4_tug891",
  "sequences": [
    { "protein": { "id": "A", "sequence": "RTRFPFFSDVKGDHRL…MTLCRN" } },
    { "ligand": { "id": "B", "smiles": "Cc1ccc(cc1)c2ccc(cc2COc3ccc(cc3)CCC(=O)O)F", "description": "TUG-891" } }
  ],
  "modelSeeds": [1], "dialect": "alphafold3", "version": 4
}

No SMILES for your ligand yet? PubChem is the easiest lookup.

REAL RESULT — FFA4 + TUG-891 (experimental EC50 ~0.2–0.4 µM)
iptm 0.94 · ranking_score 0.95 · ptm 0.87 · no clashes — a strong, well-calibrated result on a molecule with known real affinity. Good benchmark for judging your own macrocycle/peptidomimetic runs against: an iptm well under 0.6 deserves real skepticism about the predicted binding mode.

Covalent complexes — if the peptide/ligand is meant to covalently attach to the protein (not just non-covalent binding), that needs the bondedAtomPairs field (see Input JSON reference below).

Other input types

DNA, RNA, glycans, and specific post-translational modifications are all supported but outside day-to-day scope for this group. Working examples for all of them are in ~/alphafold3/examples/ on Woody — copy the closest one and edit.

Using the shared GPUs politely

Woody has 4× RTX A5500 GPUs (24GB each), shared across the group.

GOOD PRACTICE
Check what's free first: nvidia-smi. Pin your run to a specific idle GPU instead of grabbing all of them: --gpus device=2 (zero-indexed, picks the third GPU). For long jobs, split the slow CPU data-pipeline stage from the GPU inference stage (--run_data_pipeline=true --run_inference=false, then the reverse with --force_output_dir=true) so you're not holding a GPU idle during genetic search.

Input JSON — full field reference

Top-level fields:

FieldRequiredMeaning
nameYesJob name; used for output folder naming
modelSeedsYesList of seeds — one predicted structure per seed
sequencesYesList of protein/rna/dna/ligand entities
bondedAtomPairsNoExplicit covalent bonds (covalent ligands, glycans) — not supported for polymer-polymer bonds
userCCD / userCCDPathNoCustom Chemical Component Dictionary for molecules SMILES can't express, or that need bonding
dialectYesAlways "alphafold3"
versionYes1–4; use 4 for description field support

Protein entity: id (str or list — list means multiple identical copies), sequence, modifications (PTMs by CCD code + position), description, unpairedMsa/unpairedMsaPath, pairedMsa/pairedMsaPath (leave unset to auto-build), templates (protein only).

RNA entity: id, sequence (A/C/G/U only), modifications, description, unpairedMsa/unpairedMsaPath. No pairedMsa.

DNA entity: id, sequence (A/C/G/T only), modifications, description. No MSA fields at all — no genetic search run for DNA.

Ligand entity: id, and one of ccdCodes (standard PDB codes, e.g. ["ATP"]) or smiles. Ions are just ligands (ccdCodes: ["MG"]).

MSA control: leave unpairedMsa/pairedMsa unset to auto-build (default). Set to "" to explicitly skip. Set to an A3M string to supply your own — also pass --resolve_msa_overlaps=false on the command line for custom paired MSA, or auto-dedup can break your pairing.

Templates: templates: [] runs template-free (still builds MSA). Omit/null to auto-search.

bondedAtomPairs — atoms addressed as [entity_id, residue_id, atom_name]:

"bondedAtomPairs": [
  [["A", 145, "SG"], ["L", 1, "C04"]]
]

Output — what you get back

For job <name>, default settings (1 seed, 5 samples/seed):

<name>/
├── seed-<seed>_sample-0/ … sample-4/   # one folder per sample
├── <name>_model.cif                   # best prediction — usually what you want
├── <name>_summary_confidences.json    # scores for the best prediction
├── <name>_confidences.json            # full per-residue/atom arrays
├── <name>_ranking_scores.csv          # ranking_score for every seed/sample
├── <name>_data.json                   # input JSON, filled in with MSA/template data used
└── TERMS_OF_USE.md
MetricRangeMeaning
ranking_score≤1.50.8×ipTM + 0.2×pTM + 0.5×disorder − 100×has_clash
ptm0–1Overall fold confidence, >0.5 = probably right
iptm0–1 / nullConfidence two chains are correctly docked; null = single chain
pLDDT0–100Per-atom local confidence, in confidences.json
PAEÅ, lower betterPredicted error between residue pairs, in confidences.json

For a complex, care about one chain/interface rather than the whole thing? Use chain_iptm (chain's average interface confidence, unknown partner), chain_pair_iptm (specific pair), chain_ptm (fold confidence for one chain).
