A note on "docking": AlphaFold3 doesn't dock the way AutoDock or Glide does — it doesn't score candidate poses against a fixed receptor. It co-folds: given a protein sequence and a ligand or peptide (as SMILES), it predicts the whole bound complex's shape from scratch, in one go. There's no pose list to browse — one predicted structure, with a confidence score telling you how much to trust it. For working out how a macrocycle sits against a target, this gets you to the same place, by a different route.

1What this is

AlphaFold3 predicts the 3D structure of proteins — and, critically for this group, the structure of a protein bound to a peptide, macrocycle, or small molecule. Give it sequences (and optionally a ligand SMILES string), get back a structure file plus a confidence score telling you how much to trust it.

2Before you start

One-time checklist.

  • Be in the docker group. Ask Andrew (or whoever administers Woody) to run sudo usermod -aG docker <your-username>, then log out and back in.
  • Your files — input JSON goes in ~/af3/input/ (mkdir -p ~/af3/input ~/af3/output if it doesn't exist yet), results land in ~/af3/output/.
  • You don't manage weights or databases. Already downloaded and shared on /data/20260825_AndrewR_af3/ — every user's runs point at the same copy.

3Quick start — fold a single protein

FFA4 (Free Fatty Acid Receptor 4 / GPR120) — the group's own target — is the worked example throughout this guide, so every number you see is real, not invented.

amber text like this marks the one part you'd change for your own job — everything else is copy-paste as-is.

Step 1 — get your sequence

A protein sequence is a string of one-letter amino acid codes (a FASTA sequence). If you don't have one, get it from UniProt — search your protein, open its entry, copy the sequence.

Step 2 — write the input file

Save as ~/af3/input/ffa4_monomer.json:

jsonffa4_monomer.json
{
  "name": "ffa4_monomer",
  "sequences": [
    {
      "protein": {
        "id": "A",
        "sequence": "RTRFPFFSDVKGDHRLVLAAVETTVLVLIFAVSLLGNVCALVLVARRRRRGATACLVLNLFCADLLFISAIPLVLAVRWTEAWLLGPVACHLLFYVMTLSGSVTILTLAAVSLERMVCIVHLQRGPGRRARAVLLALIWGYSAVAALPLCVFFRVVPQRISICTLIWPTIPGEISWDVSFVTLNFLVPGLVIVISYSKILQITKASRKRLTVSLAYSESHQIRVSQQDFRLFRTLFLLMVSFFIMWSPIIITILLILIQNFKQDLVIWPSLFFWVVAFTFANSALNPILYNMTLCRN",
        "description": "your protein's name/description"
      }
    }
  ],
  "modelSeeds": [1],
  "dialect": "alphafold3",
  "version": 4
}

id is just a chain label — leave it as "A" for a single-chain job. modelSeeds controls the seed used for sampling — [1] is fine to start with.

Step 3 — run it

Copy-paste exactly, just swap the filename:

bashterminal
docker run -it \
    --volume $HOME/af3/input:/root/af_input \
    --volume $HOME/af3/output:/root/af_output \
    --volume /data/20260825_AndrewR_af3/models:/root/models \
    --volume /data/20260825_AndrewR_af3/databases:/root/public_databases \
    --gpus all \
    alphafold3 \
    python run_alphafold.py \
    --json_path=/root/af_input/ffa4_monomer.json \
    --model_dir=/root/models \
    --output_dir=/root/af_output

What happens while it runs

Two stages, back to back:

  1. Data pipeline (CPU only) — searches genetic databases to build an MSA. The slow part: a few minutes for a small protein, up to ~10–15 min for something FFA4's size (297 residues). Normal, not stuck.
  2. Inference (GPU) — the actual structure prediction. Fast — typically under a minute per target on our A5500s.

RangeRead as
> 0.8Confident — trust this

5Docking: protein-protein and protein-peptide/ligand complexes

The section most of the group will actually use — predicting how a peptide, macrocycle, or small molecule sits against a target protein.

5a. Protein + protein

A linear peptide or second protein chain — add a second protein entity with a different id. AlphaFold3 predicts the joint complex directly, no extra flags:

jsontwo-chain complex
{
  "name": "my_complex",
  "sequences": [
    { "protein": { "id": "A", "sequence": "TARGET_PROTEIN_SEQUENCE" } },
    { "protein": { "id": "B", "sequence": "SECOND_CHAIN_SEQUENCE" } }
  ],
  "modelSeeds": [1], "dialect": "alphafold3", "version": 4
}

5b. Protein + macrocyclic peptide or peptidomimetic

The important one for us. AlphaFold3's protein entity only understands standard linear natural-amino-acid chains — no way to represent a head-to-tail cyclized backbone, a disulfide-stapled macrocycle, D-amino acids, N-methylation, or other peptidomimetic chemistry.

The fix: represent the macrocycle as a ligand entity via its SMILES string, not as a protein entity. SMILES ring notation encodes the macrocycle directly and covers non-natural chemistry — exactly what a DeepMind AlphaFold3 maintainer recommends for this:

"One of the suggestions is to specify the whole peptide plus covalently bound ligand as SMILES string (treating short peptide as a small molecule)." okovalevskiy, DeepMind AF3 team — github.com/google-deepmind/alphafold3, issue #242

Get the SMILES from whatever you already use — ChemDraw, RDKit, PepWiz, hand-drawn:

jsontarget + macrocycle
{
  "name": "target_plus_macrocycle",
  "sequences": [
    { "protein": { "id": "A", "sequence": "TARGET_PROTEIN_SEQUENCE" } },
    { "ligand": {
        "id": "B",
        "smiles": "YOUR_MACROCYCLE_SMILES",
        "description": "macrocycle name"
      } }
  ],
  "modelSeeds": [1], "dialect": "alphafold3", "version": 4
}
SMILES + JSON: SMILES often contain backslashes (\), which JSON treats as an escape character. Double any \ to \\ before pasting, or run python3 -c "import json; print(json.dumps(input()))" to auto-escape.

5c. Protein + small organic ligand — worked example

Same pattern as 5b, with an ordinary small molecule. Worked with TUG-891, a real native FFA4 agonist:

jsonffa4_tug891.json
{
  "name": "ffa4_tug891",
  "sequences": [
    { "protein": { "id": "A", "sequence": "RTRFPFFSDVKGDHRL…MTLCRN" } },
    { "ligand": {
        "id": "B",
        "smiles": "Cc1ccc(cc1)c2ccc(cc2COc3ccc(cc3)CCC(=O)O)F",
        "description": "TUG-891, native FFA4 agonist"
      } }
  ],
  "modelSeeds": [1], "dialect": "alphafold3", "version": 4
}

No SMILES for your ligand yet? PubChem is the easiest lookup — search the compound name, SMILES is on its summary page.

6Other input types

DNA, RNA, glycans, and specific PTMs are all supported but outside day-to-day scope for this group. Working examples for all of them are in ~/alphafold3/examples/ on Woody — copy the closest one and edit.

7Using the shared GPUs politely

Woody has 4× RTX A5500 GPUs (24GB each), shared across the group.

Check what's free first:

bashterminal
nvidia-smi

Pin your run to a specific idle GPU instead of grabbing all of them:

bashterminal
docker run ... --gpus device=2 alphafold3 python run_alphafold.py ...

device=2 picks the third GPU, zero-indexed — change the number to whichever nvidia-smi shows as free.

For long jobs, split the slow CPU stage from the GPU stage so you're not holding a GPU idle during genetic search:

bashtwo-stage run
# Stage 1 — CPU only, no --gpus needed
docker run -it --volume ... alphafold3 \
  python run_alphafold.py --json_path=... --output_dir=... \
  --run_data_pipeline=true --run_inference=false

# Stage 2 — GPU, once stage 1 finishes
docker run -it --gpus device=N --volume ... alphafold3 \
  python run_alphafold.py --json_path=... --output_dir=... \
  --run_data_pipeline=false --run_inference=true

8Troubleshooting

  • permission denied on the Docker socket — not (yet) in the docker group, or shell hasn't picked up a recent change. Log out and back in.
  • Run seems to hang with no GPU activity — normal. Data pipeline is CPU-only and can take 10+ min for larger targets.
  • Out-of-memory during inference — our 24GB cards sit below AF3's verified tier (80GB A100/H100). Add these unified memory flags:
    bash
    docker run -e XLA_PYTHON_CLIENT_PREALLOCATE=false \
           -e TF_FORCE_UNIFIED_MEMORY=true \
           -e XLA_CLIENT_MEM_FRACTION=3.2 \
           ...
    If it still fails, the target is likely too large for a single 24GB card.
  • Failed to construct RDKit reference structure — couldn't generate 3D coordinates for your ligand SMILES. Try --conformer_max_iterations=<higher>, or check the SMILES is valid.
  • SMILES-related JSON errors — check backslash escaping, §5b.
  • Job name collision — AF3 timestamp-suffixes new output rather than overwriting, unless --force_output_dir=true.
  • Full flag list: docker run alphafold3 python run_alphafold.py --help

Input JSON — full field reference
FieldReq.Meaning
nameYesJob name; used for output folder naming
modelSeedsYesList of seeds — one predicted structure per seed
sequencesYesList of protein/rna/dna/ligand entities
bondedAtomPairsNoExplicit covalent bonds (covalent ligands, glycans)
userCCD / userCCDPathNoCustom Chemical Component Dictionary for molecules SMILES can't express, or that need bonding
dialectYesAlways "alphafold3"
versionYes1–4; use 4 for description support

Protein entity: id (str or list — list means multiple identical copies), sequence, modifications (PTMs by CCD code + position), description, unpairedMsa/unpairedMsaPath, pairedMsa/pairedMsaPath (leave unset to auto-build), templates (protein only).

RNA entity: id, sequence (A/C/G/U only), modifications, description, unpairedMsa/unpairedMsaPath. No pairedMsa.

DNA entity: id, sequence (A/C/G/T only), modifications, description. No MSA fields — no genetic search run for DNA.

Ligand entity: id, and one of ccdCodes (e.g. ["ATP"]) or smiles. Ions are just ligands (ccdCodes: ["MG"]).

MSA control: leave unpairedMsa/pairedMsa unset to auto-build (default). Set to "" to explicitly skip. Set to an A3M string to supply your own. Custom paired MSA also needs --resolve_msa_overlaps=false on the command line, or auto-dedup can break your pairing.

Templates: templates: [] runs template-free (still builds MSA). Omit/null to auto-search.

bondedAtomPairs — covalent ligands/glycans only, not polymer-polymer bonds. Atoms addressed as [entity_id, residue_id, atom_name]:

json
"bondedAtomPairs": [
  [["A", 145, "SG"], ["L", 1, "C04"]]
]

userCCD — custom molecules needing specific bonding/atom names/ideal coordinates SMILES can't express (full mmCIF spec in ~/alphafold3/docs/input.md).

Glossary

Quick lookup for terms and code variables used throughout this guide — linked from the main text wherever they first appear.

Concepts

FASTA sequence

A protein/DNA/RNA sequence written as a plain string of one-letter codes (e.g. MKV...). The standard format most sequence databases (UniProt, NCBI) export.

SMILES

A compact text notation for a molecule's 2D structure (atoms, bonds, rings), e.g. Cc1ccc(cc1).... How AlphaFold3 takes in any ligand, macrocycle, or peptidomimetic that isn't a plain protein chain.

Co-folding vs. "docking"

AlphaFold3 predicts a whole bound complex's 3D shape from scratch in one pass, rather than scoring candidate poses against a fixed receptor the way AutoDock/Glide do. One predicted structure comes out, with a confidence score — no pose list to browse.

MSA (Multiple Sequence Alignment)

A collection of evolutionarily related sequences, aligned against your query. Built automatically by searching genetic databases (the data pipeline stage) — related sequences reveal which positions co-vary, a strong signal for 3D shape.

Data pipeline

The first stage of a run: CPU-only genetic database search that builds the MSA (and finds structural templates, if applicable). The slow part of a run.

Inference

The second stage: the GPU actually predicts the 3D structure from the featurised input. Fast compared to the data pipeline.

Chain / chain ID

One molecular entity in your input (e.g. "id": "A") — a protein, a ligand, a strand of DNA/RNA. A complex is just multiple chains in one sequences list.

Macrocycle

A large ring-shaped molecule, e.g. a peptide cyclized head-to-tail or via a disulfide staple. AlphaFold3's protein entity can't represent the ring closure — see §5b — so macrocycles go in as a ligand entity via SMILES instead.

Peptidomimetic

A peptide-like molecule with non-natural chemistry (D-amino acids, N-methylation, non-peptide linkers). Same reasoning as macrocycles: represent as a SMILES ligand, not a protein entity.

Ligand entity

The "ligand": {...} block in an input JSON. Used for small molecules, macrocycles, peptidomimetics, and ions — anything specified by SMILES or a CCD code rather than an amino-acid sequence.

CCD (Chemical Component Dictionary)

The PDB's standard library of named chemical building blocks (e.g. "ATP", "MG"). Ligands can reference a CCD code instead of SMILES when the molecule is already standard/recognized.

Structural template

A known 3D structure (from the PDB) AlphaFold3 can use as a hint for a protein chain, alongside sequence-based prediction. Auto-searched by default; protein entities only.

Covalent bond / bondedAtomPairs

For when a ligand/peptide is meant to be chemically bonded to the protein, not just non-covalently bound. See §5d and the full reference.

Confidence metrics

pLDDT

Per-atom local confidence, 0–100. Tells you which specific loop/domain to trust within an otherwise-good structure.

PAE (Predicted Aligned Error)

Predicted positional error in Å between every pair of residues, lower = better. Most useful for judging confidence at an interface between two chains.

pTM / ptm

Predicted TM-score, 0–1: confidence in the overall fold. >0.5 is a reasonable sign the fold is right.

ipTM / iptm

Predicted interface TM-score, 0–1 (or null for single-chain jobs): confidence that two chains are correctly docked against each other. The number that matters most for a binding question.

ranking_score

The overall score AlphaFold3 uses to pick its best prediction: 0.8×ipTM + 0.2×pTM + 0.5×fraction_disordered − 100×has_clash.

fraction_disordered

Fraction of the structure predicted as disordered/unstructured (by accessible surface area), 0–1.

has_clash

Whether the predicted structure has significant atomic clashes (true/false).

Infrastructure

Docker / container / image

Docker packages AlphaFold3 and all its dependencies into a self-contained image; docker run starts a container (a running instance of that image) to execute a job. You don't install AlphaFold3's Python environment yourself. --volume host:container makes a folder on Woody visible inside the container at a given path.

GPU / VRAM

The graphics card that runs the inference stage. VRAM is its onboard memory — ours (RTX A5500) have 24GB each, below AlphaFold3's officially-verified 80GB tier.

Unified memory

A GPU memory mode that lets the GPU spill into system RAM when it runs short of VRAM, at some speed cost. How we work around our 24GB cards being under AlphaFold3's verified spec.

Seed (modelSeeds)

A random seed controlling sampling; each seed produces its own set of predicted structures (5 samples per seed, by default). Running more than one seed is one way to sanity-check an uncertain prediction.
